# minecraft-data Generation Pipeline

MineRider never hand-maintains version-specific protocol data. Packet ids,
names, field layouts, state/direction mappings and the version constants
are generated from [PrismarineJS minecraft-data](https://github.com/PrismarineJS/minecraft-data)
by the `minerider-codegen` crate.

Target version: **Minecraft Java Edition 1.21.4, protocol 769**.

## Layout

```text
crates/
  minerider-codegen/            build-time generator (never a runtime dep)
    src/
      model.rs                  parsed JSON model (TypeDef, Complex, ...)
      parse.rs                  protocol.json / version.json loader + validation
      ir.rs                     resolved IR: states, directions, packets, types
      emit.rs                   Rust code emission
      main.rs                   CLI (regenerate / --check)
    vendor/minecraft-data/pc/1.21.4/
      protocol.json             vendored source of truth (committed)
      version.json
  minerider-protocol/src/generated/   OUTPUT — never edit by hand
    mod.rs
    versions.rs                 ProtocolVersion, V1_21_4, SUPPORTED
    v1_21_4/
      mod.rs                    packet count constants
      types.rs                  53 shared named types
      handshaking.rs status.rs login.rs configuration.rs play.rs
```

Every generated file starts with:

```rust
// @generated by minerider-codegen
// Source: minecraft-data
// Minecraft version: 1.21.4
// Protocol version: 769
// DO NOT EDIT MANUALLY
```

## Regenerating

```sh
cargo run -p minerider-codegen            # rewrite generated/
cargo run -p minerider-codegen -- --check # drift gate: exit 1 if committed files differ
cargo test -p minerider-codegen           # includes the drift + determinism tests
```

The drift gate (`crates/minerider-codegen/tests/drift.rs`) regenerates in
memory and compares byte-for-byte with the committed files, so hand edits
and forgotten regenerations fail CI.

## Generated API

Per state module (e.g. `generated::v1_21_4::login`):

- `PacketXxx` structs with typed fields, implementing
  `traits::Encode` / `traits::Decode`.
- `CLIENTBOUND_*_ID` / `SERVERBOUND_*_ID` constants.
- `Clientbound<State>Packet` / `Serverbound<State>Packet` enums with
  `id()`, `name()`, `decode(id, reader)` (integer match dispatch, no string
  lookups in the hot path) and `Encode` (writes id varint + payload).
- `clientbound_packet_name(id)` / `serverbound_packet_name(id)`.

`versions.rs` exposes:

```rust
pub struct ProtocolVersion { pub protocol: i32, pub minecraft: &'static str }
pub const V1_21_4: ProtocolVersion = ProtocolVersion { protocol: 769, minecraft: "1.21.4" };
pub const SUPPORTED: &[ProtocolVersion] = &[V1_21_4];
```

## Supported minecraft-data types

Natives: `bool`, `i8`..`i64`, `u8`..`u64`, `f32`, `f64`, `varint`,
`varlong`, `string`, `UUID`, `position`, `void`, `restBuffer`,
`anonymousNbt`, `anonOptionalNbt`.

Complex kinds: `container` (incl. anonymous inlining), `array`
(countType / fixed count / sibling-field count), `option`, `switch`
(sibling and `../` compareTo, nested switches, defaults), `mapper`,
`buffer`, `pstring` (varint only, UTF-8 approximation — legacy ping),
`bitfield`, `bitflags`, `topBitSetTerminatedArray`,
`entityMetadataLoop` (255-terminated), `registryEntryHolder`,
`registryEntryHolderSet`.

Anything else fails generation with a precise error naming the packet,
field and source type — nothing is silently skipped.

Notable modeling decisions:

- **Recursive types** (e.g. `SlotDisplay`) are detected per direction with
  a Tarjan SCC over edges that don't break recursion (Vec-backed shapes
  break cycles); intra-cycle references are emitted as `Box<T>`.
- **Direction-local name collisions** (`encryption_begin`,
  `tab_complete`, `held_item_slot`, `position`, `vehicle_move`,
  `abilities` have different layouts per direction) are disambiguated with
  a `Clientbound`/`Serverbound` suffix, e.g.
  `PacketEncryptionBeginServerbound`.
- **Switch on an option/switch-enum discriminant** (scoreboard packets)
  flattens the discriminant to `Option<i64>`; branch keys match `Some(n)`.
- **Shared types** live in `types.rs`; state modules reference them via
  `super::types::` — no duplication between states.
- **NBT** uses a safe recursive-descent codec with depth (64) and node
  (1M) caps.
- Strings, arrays and buffers are bounded by the remaining packet bytes;
  counts are checked before any allocation.

## Runtime bounds

Generated decoders share the protocol crate's protections: frame-size
limits, decompressed-size limits, VarInt length limits, `ensure_consumed`
(trailing bytes rejected at packet level), no panics from server input.
`#![forbid(unsafe_code)]` holds for the whole protocol crate.

## Adding a future Minecraft version

1. Vendor `minecraft-data/pc/<version>/{protocol,version.json}`.
2. Extend the version table in the generator (`emit.rs` constants) and the
   output layout (`generated/v<version>/`).
3. Regenerate; unsupported shapes fail loudly — add support in the emitter
   plus a regression test.

The runtime never sees raw protocol numbers: clients take a
`ProtocolVersion` explicitly (`ClientConfig::version`).
